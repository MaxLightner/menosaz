# Mizato release — 2026-10-19

Runtime: GitHub Pages frontend; Supabase Auth, database, Storage and menu-api Edge Function. No operational local server or local database is required.

## Shipped

- Reconciled the latest menu library, image editor and customer cart fixes with table QR simplification and network recovery.
- Applied versioned staff, attendance, feedback and customer-club schema/API migrations to the existing Supabase project; reused profiles and business memberships.
- Shared waiter entry QR is scoped to the business. Server allowlist is checked before SMS and again after verified OTP. Disabled membership denies operations immediately.
- Attendance has one open shift per employee/business, explicit clock-out and logout clock-out. Overtime is an estimate against configured working duration, interpreted in the business timezone, not a payroll determination.
- Delivery identity is derived from order events. Feedback requires a delivered order belonging to the requesting guest; duplicate reviews are rejected.
- Marketing consent is separate from providing a phone number. Unsubscribe uses an unguessable token. Club visit counts represent sessions associated with identified feedback, not unobserved visits.
- Every fresh login requires terms acceptance. Terms open in a nested dialog without discarding the OTP challenge. Version and acceptance time are recorded on the server; remembered sessions remain native Supabase Auth sessions.
- QR modal selects the requested table, uses stable point URLs and offers PNG download and individual/batch print. QR no longer opens a redundant menu preview for each table.
- Product removal is recoverable archiving; order history remains intact. Photo controls and price editing retain mobile-safe layout.
- Image uploads enforce square product images and 1 MiB maximum on the server. Content-based filenames reuse identical uploads within the same business and purpose. Registration serializes a 100 MiB per-business storage guard. Existing unreferenced images are retained, not automatically deleted.
- Read polling and OTP/mutation rate limits have separate buckets; ordinary polling does not exhaust the OTP budget.

## Verification

- TypeScript and production build passed; GitHub Pages workflow checks catalog/access/order/payment/customer/image regressions.
- `scripts/verify-staff-feedback.sql` ran on Supabase inside a rolled-back transaction with generated fixtures: staff eligibility/claim, shift idempotency, role/tenant boundaries, terms, delivered-only feedback, duplicate/forged feedback, anonymous privacy, opt-out and disabled access. Fixtures were rolled back.
- Gallery registration deduplication and non-square rejection were checked in a rolled-back Supabase transaction.
- `scripts/check-public-release.mjs --site` checks the actual public site, anonymous QR resolution and private-data denial.
- `scripts/check-live-staff.mjs` checks live negative authentication/permission paths and DELETE CORS without sending SMS or creating real orders.
- Authenticated browser inspection confirmed manager staff, feedback and club screens load from the live backend, and selecting table 3 opens its own QR.

## Practical limits

- Fresh SMS delivery was not requested during this release; the existing OTPy integration remains in place. A new phone login needs a code from its owner for a complete handset test.
- Audible alerts require the user to activate sound in the browser. Vibration depends on device/browser support. Closed-app Web Push and marketing SMS campaigns are not part of this release.
- Printing was prepared and QR generation verified; physical printer output and vibration require the user's device.
