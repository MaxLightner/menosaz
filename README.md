> نسخه فعلی از API محلی استفاده می‌کند. برای اجرای کامل، `pnpm server` و `pnpm dev` را هم‌زمان اجرا کنید. ورود پیامکی فعلاً آزمایشی است. راهنمای سرور و چندمنویی در بخش «سرور و مدیریت چند منو — نسخه فعلی» پایین آمده است. دستورهای قدیمی Firebase مربوط به نسخه پیشین‌اند.

# منوساز — نسخه اصلاح‌شده مخزن GitHub

مبنا: MaxLightner/menosaz، شاخه main. فایل‌های مخزن در این پوشه دریافت شده‌اند؛ اتصال‌ها و مدل داده React/Firebase مبنا هستند. اصلاحات فعلاً محلی‌اند و در GitHub منتشر نشده‌اند. کد سه نمای جدید در فایل‌های RestoredCustomerApp، RestoredWaiterApp و RestoredKitchenApp است. فایل‌های نمای قدیمی برای مقایسه حفظ شده‌اند.

## اجرای پیش‌نمایش

Node.js ۲۲٫۱۲ یا بالاتر و pnpm لازم است؛ Vite 8 موجود در مخزن استفاده می‌شود.

```text
pnpm install
pnpm dev
```

یا مستقیم:

```text
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4180
```

مسیرها:

- صفحه عمومی: http://127.0.0.1:4180/?view=website
- منوی مشتری: http://127.0.0.1:4180/?view=customer&table=4
- گارسون: http://127.0.0.1:4180/?view=waiter
- رستوران: http://127.0.0.1:4180/?view=kitchen

برای ورود و خروج آزمایشی از دکمه ورود صفحه اول استفاده شود. گزارش کوتاه بعد از ورود و دکمه داشبورد نمایش داده می‌شود. صفحه اول در حالت خارج از حساب هم قابل استفاده است. تنظیم رنگ و پس‌زمینه در داشبورد مدیر است؛ مشتری تنظیم پس‌زمینه ندارد.

## حالت محلی و Firebase

فایل .env.local برای پیش‌نمایش دارای VITE_LOCAL_PREVIEW=true است. داده‌های آزمایشی در کلیدهای menosaz_local_preview_v2 مرورگر ذخیره می‌شوند؛ listenerهای Firebase و نوشتن در پایگاه واقعی غیرفعال‌اند. تب‌های یک مرورگر از storage همگام می‌شوند. ورود محلی آزمایشی است و به Google متصل نمی‌شود.

برای بررسی اتصال واقعی، این پرچم باید false شود و تنظیمات موجود Firebase، ورود Google، نقش کاربران و مجوزهای Firestore/Storage بررسی شوند. ورود/خروج واقعی از Firebase Auth استفاده می‌کند. آپلود پس‌زمینه واقعی از Firebase Storage استفاده می‌کند و به bucket و مجوزهای صحیح نیاز دارد. این اتصال‌ها در این مرحله روی سرویس واقعی آزمایش نشده‌اند. هیچ انتشار یا تغییر قواعد دسترسی سرور در این مرحله انجام نشده است.

نمونه منوهای کافه، هتل، آبمیوه و رستوران نارنج، نمایشی‌اند. سفارش نمونه این مجموعه‌ها به پایگاه داده واقعی ارسال نمی‌شود. نوار بالای صفحه، سفارش‌های جاری مجموعه فعلی و مثال‌های مشخص‌شده با برچسب نمایشی را نمایش می‌دهد؛ فید عمومی چند مجموعه مستقل هنوز به داده عمومی چندرستورانی نیاز دارد. نام و یادداشت خصوصی مشتری در نوار عمومی نشان داده نمی‌شود.

## رفتار سفارش‌ها

گارسون فقط غذا حذف می‌کند یا توضیح گارسون می‌نویسد؛ افزودن غذا و تغییر تعداد در این نما وجود ندارد. دریافت وجه و ارسال با یک تغییر وضعیت ثبت می‌شود. تیک تأیید رستوران فقط از نمای رستوران ثبت می‌شود و تیک تحویل فقط پس از پرداخت و تأیید رستوران فعال است. هر دو تیک پنجره تأیید مجدد، انصراف و ضربدر دارند. حذف غذا یا اصلاح توضیح پس از ارسال، تأیید رستوران را باطل و ارسال دوباره را لازم می‌کند. بعد از تحویل توضیحات جمع می‌شود و کارت خاکستری می‌شود.

فیلدهای افزوده‌شده: Order.restaurantConfirmed، OrderItem.waiterNotes، Business.menuPalette، Business.menuPaper، Business.menuBackgroundImage. این فیلدها اختیاری‌اند تا داده‌های قبلی قابل خواندن باشند. customer notes و waiter notes جدا هستند. مجوز نقش و کنترل انتقال وضعیت در سرور برای محیط واقعی هم باید اجرا شود.

قیمت‌ها و آیتم‌های مجموعه اصلی از همان پروژه AI Studio خوانده می‌شوند؛ داده چاپی ۶۰ موردی نسخه HTML قدیمی به‌جای منبع Firebase وارد نشده است. چیدمان نسخه مشتری شامل عکس مربع، متن خوانا، نمای کلی دو ستونه، مقایسه توضیحی حداکثر پنج مورد، جزئیات بیشتر، سفارش و مدل آزمایشی روی میز است.

## بررسی

```text
pnpm build
pnpm lint
node --experimental-strip-types scripts/test-order-rules.mjs
```

فایل‌های scripts/restore-context.cjs، finish-public-site.cjs و دیگر اسکریپت‌های مهاجرت یک بار استفاده شده‌اند و نباید دوباره اجرا شوند. برای ادامه ویرایش، مستقیماً src/ و public/ را تغییر دهید.

فونت محلی استعداد با مجوز OFL در public/fonts است. منبع فونت: https://github.com/aminabedi68/Estedad . الگوهای حاشیه‌ای منو SVG محلی هستند؛ جست‌وجوی الهام: https://www.canva.com/menus/templates/background/ . تصاویر نمونه نمایشی‌اند؛ اصلاح کامل تصاویر طبق درخواست به بعد موکول شده است. تصاویر جدیدی که قبلاً آماده شده‌اند فقط برای نمونه استفاده شده‌اند و عکس واقعی محصولات مجموعه محسوب نمی‌شوند.


نمونه منوها در یک ردیف افقی با چهار کارت در دسکتاپ و پیمایش در موبایل نمایش داده می‌شوند. نوار سفارش‌های انجام‌شده بالای همین بخش است؛ موارد نمایشی مشخص شده‌اند. ورود با دکمه مشاهده منو، دکمه بازگشت به سایت یا داشبورد دارد. لینک مستقیم ?view=customer&table=7 فقط منو را باز می‌کند و هیچ ناوبری به سایت یا نقش‌های دیگر ندارد. منوهای نمونه با دسته‌ها و توضیحات مقدار و طعم تکمیل شده‌اند؛ نام مجموعه‌ها و قیمت‌ها نمایشی‌اند.


## سرور و مدیریت چند منو — نسخه فعلی

در دو ترمینال `pnpm server` و `pnpm dev` اجرا شوند. سایت روی 4180 و API روی 4181 است؛ Vite مسیر /api را به سرور محلی می‌فرستد. Node 24 لازم است. سرور SQLite با ذخیره پایدار در server/data/menosaz.sqlite دارد. این پوشه شامل داده و نشست‌هاست؛ آن را داخل زیپ یا گیت قرار ندهید.

VITE_BACKEND=true مسیر جدید را فعال می‌کند. ورود شماره موبایل و کد شش‌رقمی با مهلت دو دقیقه، حداکثر پنج تلاش، محدودیت دریافت مجدد، نشست HttpOnly و خروج سروری انجام می‌شود. با SMS_MODE=demo فقط در محیط غیر production کد آزمایشی به کاربر نمایش داده می‌شود؛ هیچ پیامکی ارسال نمی‌شود. در production سرویس و قالب پیامک باید تنظیم شوند و نسخه نمایشی پذیرفته نمی‌شود. اتصال آماده کاوه‌نگار فقط بعد از تنظیم و آزمایش کلید و قالب قابل استفاده است؛ در این مرحله ارسال واقعی آزمایش نشده است.

هر مجموعه چند منو با آیتم و ظاهر مستقل دارد. مدیر می‌تواند منو تعریف کند، غذا اضافه کند و غذای موجود را به منوی دیگر منتقل کند. لینک مستقیم منو شامل view=customer&table=4&menu=MENU_ID&business=BUSINESS_ID است. سفارش‌ها برای مجموعه جمع می‌شوند. منوهای نمایشی صفحه اول همچنان داده نمونه‌اند.

قیمت و گزینه‌های سفارش از داده سرور محاسبه می‌شوند. تأیید قبل از پرداخت و تحویل قبل از تأیید رستوران در API رد می‌شود. اطلاعات مشتری در نوار عمومی نمایش داده نمی‌شود. حساب مدیر دسترسی به عملیات مجموعه خود دارد؛ حساب‌های جداگانه کارکنان و استقرار عمومی هنوز پیکربندی نشده‌اند. Firebase قدیمی در حالت API استفاده نمی‌شود؛ قوانین پیشنهادی Firestore بسته شده‌اند، ولی هیچ قانون یا سروری در اینترنت مستقر نشده است.

داشبورد زیر عرض 900 پیکسل از MobileDashboard قبلی با نوار پایین استفاده می‌کند و در دسکتاپ پنل راست حفظ شده است. پیش‌فرض هر دو نمای مدیریت لیست غذاهای منو است. ۱۵ رنگ و ۱۶ زمینه SVG مستقل از تصویر غذا یا منظره، با فیلتر نوع مجموعه و مناسبت و پیمایش افقی اضافه شده‌اند. الهام جست‌وجوی چاپی: https://alohacafepune.com/menu و https://www.vectorstock.com/royalty-free-vectors/coffee-menu-background-vectors . زمینه‌ها طراحی محلی‌اند و فایل‌های این سایت‌ها کپی نشده‌اند.

آزمون سرور: `node scripts/test-backend.mjs`؛ آزمون یک پایگاه موقت مستقل می‌سازد و اطلاعات کاری را تغییر نمی‌دهد. مدیریت داده‌های قدیمی مرورگر به SQLite به‌طور خودکار انجام نشده است؛ داده‌های محلی قبلی محفوظ هستند و پایگاه سرور با داده نمونه اولیه شروع شده است.
